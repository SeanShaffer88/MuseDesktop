# Known limitations

Honest list of what MuseDesktop does not do or has not proven yet. Kept current as work proceeds.

## Verification status

- **Verified on a real Windows machine (2026-10-23, v0.1.2):** startup (clean log, WebView2 ready), sign-in, and voice — confirmed by the user with the app log. (v0.1.0 crashed at startup; v0.1.1 fixed it; v0.1.2 is the first fully verified line.)
- **Still unverified at runtime:** tray menu items exercised end-to-end, close-to-tray, Start-with-Windows autostart, a completed download with progress/ETA, and F11 full screen — these run through `RELEASE_CHECKLIST.md` on the next on-machine pass. CI green alone is never treated as "it works".
- **New in v0.2.0, also runtime-unverified:** the update notice appearing (and the ⋯ item opening the release page), download cancel / click-to-open / Save-As prompt / custom downloads folder, clear-browsing-data sign-out, and WebView2 suspend-after-5-minutes-in-tray with clean resume. All are covered by new `RELEASE_CHECKLIST.md` items.
- **New in v0.3.0, also runtime-unverified:** profile add/switch/remove (including the restart hand-off), the link context-menu items, and the NSIS installer (install, upgrade-in-place, uninstall with both data choices). Covered by new `RELEASE_CHECKLIST.md` items.
- **New in v0.5.0 (Slice 1), runtime-unverified:** find in page, print / save-as-PDF, Back/Forward history dropdowns, always-on-top pin, focus mode (F8), the second window, per-profile window placement, Ctrl+Shift+T restore, classified load-failure messages with one-shot network auto-retry, and the profile name in the window title. All are on the `RELEASE_CHECKLIST.md` S1 pass list; CI/local build green is not field verification.
- **New in v0.6.0 (Slice 2), runtime-unverified:** the parallel downloads manager, pause/resume (including the practical `UserPaused` interrupt-reason behavior the tracker keys on), in-session retry via the hidden web view, history search/filter/sort with failed records and the 200/1000 caps, Copy path / Open with… / Delete file, the completion balloon, taskbar progress states, per-profile downloads folders, collision auto-rename / ask-where-to-save, and the speed readout. All are on the `RELEASE_CHECKLIST.md` S2 pass list.
- **Middle-click / Ctrl+click audit (v0.5.0, S1 #11):** those gestures reach the app through WebView2's new-window path, exactly like target=_blank, so the existing link policy already governs them (in-app hosts stay, other http(s) goes to the browser, dangerous schemes are blocked). Core tests pin the classification for every host class. No separate handling exists or is needed.

## Behavior

- **No tabs.** Muse's own UI is the tab strip; links that would open a tab follow the link policy (in-app hosts replace the page, everything else goes to your browser). Since v0.5.0 there is a session back/forward history (right-click or long-press Back/Forward) and an optional lightweight second window on the same profile — still no tabs, and the second window has no tray/settings/downloads duties and does not remember its placement.
- **F11 full screen** is handled by the app window; when keyboard focus is inside the web content, some keys are consumed by the page first (standard WebView2 accelerator behavior). Pages that request full screen themselves (e.g. video) are honored via `ContainsFullScreenElementChanged`.
- **Downloads** run in parallel since v0.6.0 (S2): the status bar shows the single-download wording for one file and an aggregate for several, and the Downloads window's *Active downloads* list manages each one (pause/resume via WebView2 where it reports `CanResume`, cancel, and retry for failures). Status-bar cancel (✕) still acts on the most recent download only. Honest limits that remain: **pause is WebView2's**, so a server without range support may restart a resumed file from zero (WebView2 reports that itself); **retry is this-session only** — download addresses are never stored, so once the app exits a failed download can only be re-downloaded from the chat, and a retry whose link has expired loads invisibly and starts nothing (see DECISIONS.md); **Delete file in the Downloads window is permanent** (it does not use the Recycle Bin) and removes the history entry; the completion balloon is a tray balloon, subject to Windows notification/quiet-hours settings. Files land in your Downloads folder unless a profile override or the shared folder in Settings says otherwise, or ask-where-to-save is on; when the target file already exists the collision setting applies (auto-rename by default).
- **Clearing data** is available in Settings (*Clear browsing data and sign out*) since v0.2.0; a partial clear (cookies only, cache only) is not offered.
- **Tray suspend:** after 5 minutes hidden in the tray the web view is suspended to free memory (Settings can turn this off). Suspend is a WebView2 feature — a page in the middle of something (e.g. a voice call) can decline it, and streaming replies pause while suspended; everything resumes when you reopen the window.
- **Profiles (v0.3.0):** switching profiles restarts the app (a WebView2 environment is bound to its data folder for the process lifetime). The profile you're currently running can't have its data folder deleted from Settings — removing it unlists it, and its folder stays on disk (delete `%LOCALAPPDATA%\MuseDesktop\WebView2-<id>` by hand if you want it gone). Settings like zoom and downloads are shared across profiles; the sign-in/session data and (since v0.3.1) the restored last page are per-profile.
- **Installer (v0.3.0):** the NSIS installer is per-user (no admin, no UAC) and unsigned, like the zip — SmartScreen may warn on first run. Installing over an existing install (upgrade) replaces the program files in place; your data folders are never touched by an upgrade.
- **Notifications** depend on Muse's web app requesting them and on Windows notification settings; the app grants the permission but cannot make Muse use it.
- **Unsigned binary.** SmartScreen will warn on first run until/unless a code-signing certificate is adopted.
- **Self-contained download (tens of MB).** Since v0.1.2 the .NET 10 runtime is bundled, so there is no .NET prerequisite — the cost is download size and that runtime patches arrive via app releases rather than the OS. Distribution is an NSIS installer plus a portable zip (since v0.3.0), for x64 and ARM64 (since v0.4.0).
- **ARM64 verification level (v0.4.0):** the ARM64 build is built and smoke-tested (window construction + WebView2 init) on GitHub's real ARM64 Windows runners in CI, but it has not been run on a retail ARM device by the maintainer. The x64 build also runs on Windows-on-ARM under emulation, so ARM users are covered either way; pick the download that matches your PC (Settings → System → About shows the system type). The installers don't block a wrong-architecture install — the file names carry the architecture for that reason.
- **New in v0.4.0, runtime-unverified:** the Downloads window (open / show-in-folder / clear), per-profile start-at-home, settings export/import round-trip, and Ctrl+, for Settings — all on the `RELEASE_CHECKLIST.md` pass list. The v0.4.0 internal refactor (download/tray/update extraction) is covered by the Core suite plus CI smoke; its on-machine behavior folds into the same pass.
- **WebView2 Runtime is a prerequisite** on the minority of Windows 10 PCs that lack it; the app detects this and links to Microsoft's Evergreen installer but does not install it for you.

## Accessibility notes

- Toolbar buttons carry tooltips and AutomationProperties names, and zoom level is text (not color-only). A full screen-reader pass over the shell and a keyboard-only end-to-end run are still outstanding.
